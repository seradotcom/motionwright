# MW05-E05-04 · Validated Component Distillation

**Status: partial implementation. No executable component is admitted.**

## Source authority and extraction

The existing Production → Distillation workstation records immutable
project-local proposals for reusable original semantic Canvas components.
A proposal requires two to four distinct positive Motion Canvas scenes
with compatible two-to-twelve typed Canvas roles. Actual owned node IDs
are resolved by canonical CAS; callers cannot provide replacement snapshots.

The variation test excludes source node IDs and names to prevent counting
identical copies as separate examples. A genuine negative source must be
present: a non-Motion-Canvas renderer, a locked Canvas object, or an
unsupported source node kind. Merely typing a rejection rationale without
such a real source does not satisfy the requirement.

An explicit original-rights declaration, source project identity and
generation/revision, and bounded requirements are persisted. Immutable
sampled Canvas snapshots survive subsequent scene edits. Imported older
project documents without distillation state remain readable.

## Human review is not executable admission

The first-party Native SDK operations component-distillation.propose and
component-distillation.review use the existing project edit CAS and owner
journal. A reviewer different from the author explicitly records a verdict,
a revision-bound rationale and the bounded Motion Canvas grammar. Reviews
cannot be silently overwritten.

Even a compatible review is only a **reviewed proposal**. It does not
install skills, evaluate executable code, grant new renderer privileges,
attest legal rights, or promote anything to the active craft library.
There is no installation/admission endpoint in this slice.

The source grammar admits original Canvas text, rectangles and circles;
arbitrary code, shaders, images, unknown fields, URLs, file execution and
network grants are not accepted. This is a source-provenance contract,
not a legal clearance or automatic aesthetic assessment.

## Verification and remaining scope

Rust, Studio and SQLite tests require actual source variations, real
counterexamples, cross-revision persistence, idempotent requests, source
immutability, independent reviewer and negative-case refusal. The browser
tests ensure empty/invalid evidence cannot be promoted.

Full distillation remains open: automated parameter extraction, a signed
component/evaluator package, multiple visual regression samples, human
craft judgment, independent license review, migrations and formal
admission. A code test PASS cannot be interpreted as user acceptance.

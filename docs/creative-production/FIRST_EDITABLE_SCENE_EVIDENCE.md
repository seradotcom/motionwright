# MW05-E15-04 — first editable scene and source reuse evidence

This bounded measurement extends the original nine-project **real
StudioService/SQLite performance benchmark**. It does not claim a real
user experience or that an application was installed from a release.

The benchmark uses 3 unrelated synthetic briefs, each in S/M/L sizes
(8/32/96 scenes). In a new disposable SQLite database for each
project, it now times independently:

- opening a new local project store;
- creating the original empty project through the service;
- from the start of the first authored source seeding step, the
  completion of the first editable scene. This step first commits a
  synthetic project brief, so the clock includes that same initial
  source edit;
- ten subsequent source revisions using the original canonical CAS
  transaction, then closing and reopening SQLite and checking that
  the exact original first scene identity still exists.

These are microsecond measurements of test data. The initial scene
timing begins after database opening and after project creation:
they are intentionally separated, and are NOT added into an invented
end-to-end user clock.

## First-use source report

The exact-source derived file first-scene-reuse.json is generated by
tooling/first_scene_reuse.py from the already-measured native Rust
acceptance_bench report. It requires all nine expected datasets,
ten correctly ordered measured edits per project, source SHA equality,
complete caches, nonzero first-scene durations and proof that the
first scene survived ten edits and reopening. It never replaces its
original source receipt and only creates a new destination if one
was explicitly requested.

Per-project and aggregate medians are measured independently for
new SQLite store open, first editable scene after project creation,
and source project reopen after ten revisions.

The reuse field reports only the existing exact-source, fingerprint-
verified preview-index work-unit count. It cannot be interpreted as
video frame regeneration avoided, saved renderer time or real
user adoption. Those fields remain null or NOT_MEASURED.

## Important missing acceptance

A real first useful result would require recruiting actual editors
and timing an installed candidate from their first launch through
an independently verified native frame/video that solves a real
creative brief. It would also require demonstrating asset reuse,
creative preference, and success across several diverse projects.
None of those facts follows from a synthetic initial scene, ten
source journal changes or a cache read.

GitHub Actions publishes source and resource-receipted measurements
for its exact checkout. They establish *technical source persistence*
only. No project acceptance, product launch or human review is
promoted by this report; all 60 private acceptance scenarios
remain NOT_RUN. MW05-E15-04 remains PARTIAL.

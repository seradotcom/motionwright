# StepSequence — fourth first-party editable composition (MW05-E05-03)

StepSequence is one editor-authored procedural step, not an automatically
generated software walkthrough. It extends the closed, versioned HeroLayout
family without changing the persisted v1 component identity namespace or
creating an alternate media renderer.

## Authoring

In Production > Components, choose StepSequence. Edit the required
category/eyebrow, step title, explanatory text and short step index
(for example "02" or "02 / 04"). The remaining two nodes are a visual
rule and the mandatory editorial-source disclaimer. All six objects
remain real, individually editable CanvasNode records and use stable
role-derived IDs across source revisions and output profiles.

The format-specific layout is deliberately different from ProductHeroReveal,
SplitExplanation and MetricEvidence:

- 16:9: numbered step, vertical graphic rule, heading and explanation
  in a separate right-hand reading region.
- 9:16: number above the headline, with explanatory copy below, a horizontal
  rule and space reserved for disclosure.
- 1:1: number and headline on the upper plane, body and disclaimer below.

All content is author-written. The disclosure is persisted as a fifth
text subject in the real native Film, not merely as UI decoration:

    STEP SEQUENCE / EDITORIAL STUDY · NOT AN OBSERVED WORKFLOW

The large index font scales with the character count of the owner-authored
label rather than assuming two digits. Invalid and over-budget copy is
refused; source text is never silently truncated.

## Native authority and editability

The canonical source change remains upsert_product_hero, routed through
Motionwright StudioService and the pinned Semwright Native SDK. Updating
preserves compatible human-owned text/object edits; overlapping generated
changes, deleted component nodes and source locks fail closed. The six
object IDs remain stable when changing between component families.

The native Film contains five semantic editable text containers and one
rule node. The animated mode uses the accepted synchronized out-cubic
entrance grammar; motion-disabled mode is a genuine static equivalent.

Rust and Studio are checked using a source-generated interop fixture,
expanded from 15 to 18 deterministic layout/aspect cases. A browser preview
is NOT independent native pixel evidence.

## Real E2E and limitations

The preexisting Native SDK > Semwright Broker > Motion Canvas > MLT
H.264/AAC master CI lane is expanded from nine to twelve original
composition variants (four families times three aspects). Each variant must:

1. Create an editable project through the canonical StudioService.
2. Render through the pinned native Broker/Driver Host.
3. Inspect actual native frames, region evidence and the six-second master.
4. Prove project bundle roundtrip and stale-source generation rejection.
5. Bind all receipts and hashes to the exact Motionwright source SHA.

A CI PASS is required before counting the additional native renders as
verified. It is not permission to publish a customer claim or proof that
real user software was captured or observed. Independent aesthetics,
source authenticity, licensing and end-user satisfaction remain untested.

MW05-E05-03 stays PARTIAL. The original 60 independent acceptance cases
stay NOT_RUN.

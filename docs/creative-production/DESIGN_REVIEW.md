# Native component design review

Status: **protocol prepared; human review not performed by the implementation agent**.

Use the `hero.motionwright` portable sample from a successful native lane for the candidate SHA. Keep the source project, the chosen output profile, the source commit and each new render receipt with the session. The sample is a typographic graphic study with a silent test soundtrack. It is not a finished launch film or a software-capture demo.

## Before editing

Confirm that the imported project has a new generation and the same editable component/object identities. Inspect the initial landscape, portrait and square native masters, not just the editorial parameter preview. Check the actual words, intentional line breaks, type weight, hierarchy, safe area, entry trajectory and final alignment. Record visible defects as defects even when transport, hash and font checks pass.

The corrected native text adapter keeps the component's text positions outside the renderer's automatic root layout. Its source-region gate catches a past automatic-repositioning regression. That gate is not proof that the composition is beautiful or that every possible copy fits.

## Ten request sequence to perform, not prefilled results

1. Change the headline to a short, meaningful product statement. Verify that the project revision advances once and a new native render contains the actual text.
2. Try copy beyond the declared layout budget. Confirm an actionable error and no project mutation. Choose an explicit shorter variant instead of accepting hidden truncation or font shrinking.
3. Edit the supporting copy directly as a human override. Save and reopen it.
4. Update the component accent. Verify that the deliberate supporting-copy override remains unchanged.
5. Ask for a component copy change that conflicts with that override. Confirm that the existing work is retained and the conflict identifies the affected field.
6. Lock the supporting-copy text, stage a scoped replacement and inspect the rejection. A lock is not overridden because the agent's rationale sounds reasonable.
7. Unlock the text intentionally, stage a valid bounded proposal and inspect the before/after at the same playhead time. Decline one proposal, then accept a different one as a single revision.
8. Preview undo, add an unrelated style change, and verify that the inverse preserves it. Separately create a conflicting later text change and verify that undo refuses to overwrite it.
9. Switch among output aspects. Verify actual native frames after reflow. Test an ambiguous human position override: preserve it or expose the conflict instead of silently recentering it.
10. Close/reopen, create or checkout a creative branch, and continue the chosen version. Verify that stale source generations and old native frame grants cannot write/read as the current project after an import.

These requests are a bounded component review protocol. They do not replace the broader ten-request human/source-change evaluation required for the complete creative production system.

## Record observations

For each request record: original request text, reviewer identity, source SHA/generation/revision, edits the human had already made, chosen proposal, expected protected fields, resulting revision, native output/frame hashes, refusal or failure reason, and whether the result was useful. Record wall-clock time from observed events; do not estimate task duration from animation duration or dependency count.

For a visual defect, select a native frame in **Production → Native inspection**, identify the affected object when possible, state the violated constraint and visible reason, and propose a narrow repair. Use **Scoped changes** to compare the repair. Native inspection currently supports a bounded Motion Canvas receipt; it does not claim general multimodal criticism or universal native-project editing.

## Decisions that must remain separate

**Technical:** correct output dimensions/frame rate/frame count, valid source identity, no unresolved native text/font/clipping findings, verifiable file hashes, and a readable final AV artifact.

**Creative:** coherent message, typography, spacing, visual hierarchy, motion intent, rhythm, legibility, and an acceptable settled composition. A human may reject the design after every technical check passes.

**Workflow value:** whether revisions preserved work, saved effort and were preferable to editing the renderer directly. This requires observed comparison under a fair task/budget; no competitor superiority claim is authorized by this component test.

**Release:** the full v0.5 system remains open while the remaining renderers, components, source-editing, sound production, admission and user pilots are unfinished. A successful component design test does not change those requirements to PASS.

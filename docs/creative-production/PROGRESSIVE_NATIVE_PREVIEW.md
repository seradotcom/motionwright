# v0.5 MW05-E03-02 — progressive native PNG review cadence

Motionwright's Program viewer already supports read-only inspection of the exact
PNG frames generated by the pinned Semwright Native SDK / Broker / Driver Host.
This change improves the interaction with those genuine readback artifacts:
the user sees sparse verified frame samples while the editorial transport is
playing and an exact, source-verified frame after the playhead stops.

## What the two request tiers mean

**Sampled scrub:** while transport is playing, the viewer starts at most one
native frame read every 250 milliseconds. There is at most one outstanding
read at any instant. Outdated read responses are not displayed for a newer
target frame. No pixels are interpolated or generated locally.

**Settled exact:** when transport is paused or a single frame is selected,
the viewer waits for 120 milliseconds without another target change and
requests the exact native frame index resolved from the original immutable
render receipt. It does not round away scene-local timing or relink an asset.

During a slow readback, the previously verified source PNG may remain visible.
The viewer explicitly labels it as **held**, displays its actual frame number,
and distinguishes it from the requested playhead frame. Errors fail closed,
never present a failed frame as current and require explicit retry.

A small LRU cache retains at most three source PNG frames and 32 MiB of
uncompressed input-container bytes, scoped to the current project ID,
generation, revision, original preview grant token and native segment.
Cached bytes are copied on admission. The viewer revokes Blob object URLs
on replacement or unmount. Changing a grant or source revision cannot reuse
the previous cache or revive old media.

The backend still checks the saved project revision both before and after
reading a native PNG and resolves the source-bound grant; the frontend
accepts only bounded PNG containers. The user cannot browse arbitrary
filesystem paths or mint a render grant from this view.

## What has NOT been implemented

This is a progressive **read scheduling** system, not a progressive
resolution/quality renderer. Every presented frame is a native source PNG;
there is no first-party thumbnail generator, altered pixel reconstruction,
AI frame hallucination, new image pipeline, native audio playback, or
guaranteed continuous frame-rate preview. The 4Hz figure is a maximum
request *start cadence*, not a measured native throughput result.

Complete MW05-E03-02 requires source-verified lower-resolution render
tiers, measured bandwidth and time-to-preview budgets, verified reuse across
all native renderer families and independent perceptual/editor testing.
The tracked requirement remains partial.

## Acceptance evidence

A pure deterministic scheduling suite verifies the 250ms scrub interval,
120ms exact settle, no second in-flight request, suppression after failure,
bounded LRU cache and PNG validation. The existing Tauri-IPC Playwright
tests additionally verify that source grant tokens, project ID and revision
are transmitted without local filesystem paths; old readbacks are not
revived after a project mutation. A new delayed-response browser scenario
checks that rapid seeks converge to the final exact frame without
concurrent native reads.

GitHub Actions runs the Studio build, source policies and Chromium tests.
No synthetic Playwright PNG is considered an actual Semwright render
or independently verified source. Existing native CI continues to own
actual renderer/media proof. The 60 private acceptance cases remain NOT_RUN.

## Integrated technical acceptance

Rust domain integration tests construct three independent creative scenes
within one project, plus an immutable first-party capture source registry and
its original authored claim. A revised metric must leave the generic product
stage, procedural objects/camera and capture record unchanged; an authored
stage copy change must preserve procedural, metric and capture source state.
The source project must round-trip through serialization, retaining all four
source families. A mandatory shared BrandProfile blocks unauthorized colors
for both stage and procedural original components.

Studio TypeScript integration tests reproduce all four source families, the
independent project changes, immutable claim provenance and BrandProfile
refusals. A native Film cross-feature test also creates three contiguous
source-owned scenes (original ProductStage, seeded geometry and an authored
fixed-point source label) and projects their timeline to one editable Film
with 540 exact 30-fps frames, three shots and actual semantic text subjects.
It does not replace the actual source-pinned H.264 render evidence per family.

These domain/unit fixtures use declared source hashes only:
actual imported JSON/PNG byte equality and mask-pixel coverage are separately
proved by canonical SQLite and browser/native CI. The in-memory test is not
misrepresented as physical screenshot evidence.

A separately pinned joint-master experiment renders the three original
source families **together** as one 540-frame native Film and independently
decodes the H264/AAC MP4 at all three scene centers. See
[Joint native master](JOINT_NATIVE_MASTER.md). The exact-HEAD CI and human
creative acceptance are distinct.

Independent exact-SHA workflows produce actual native Film H.264/AAC masters
for the original Stage, procedural generator and measured source, plus actual
first-party Chromium capture evidence. The rendered PNG and decoded MP4
checks are not replaced by the editorial Studio SVG preview. Only the exact
integrated PR head can establish that the four code contracts are compatible.

## Explicitly incomplete work

This integration does not certify customer-app captures, legal rights,
creative quality or measurement truth. Remaining requirements include
external authorized capture and visual asset admission to ProductStage,
native 3D device/lighting/camera, general time series and chart grammar,
advanced audio choreography, generation providers, external NLE media,
cache-performance contracts, competitive benchmarking and human creative
user testing.

The requirement-status ledger is the acceptance authority. MW05-E06-03,
E06-04, E07-01 and E07-02 remain partial until their remaining scopes are
independently implemented and accepted.

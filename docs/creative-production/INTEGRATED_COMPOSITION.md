# Integrated creative composition — Motionwright v0.5

Status: **bounded integration, not complete v0.5 acceptance**.

Four versioned source contracts now share the same project, SQLite journal,
Semwright Native SDK application and Studio Production workstation:

- Original generic ProductStage (MW05-E07-01): browser, panel and handset
  silhouettes with 14 editable native objects, stable screen/focus identities,
  an unremovable-while-bound original-graphic disclosure and rights declaration.
- First-party capture registry (MW05-E07-02): actual repeatable Chromium
  redacted PNG with independently decoded evidence, and source-triple Asset
  identity for original PNG, receipt JSON and source fixture-data JSON. This
  is a controlled local app test, never a claim of real customer activity.
- Measured data (MW05-E06-03): source SHA-256 verified bounded JSON/CSV,
  fixed-point measured units and editable counter/label/explicit-axis bar
  bindings with targeted dependency invalidation.
- Procedural fields (MW05-E06-04): bounded, seeded deterministic original
  shapes with stable editable IDs, optional native frame keys and no
  executable plugin/shader capability.

## Integrated technical acceptance

Rust domain integration tests construct three independent scenes within one
project. A revised metric must leave the generic product stage and procedural
objects/camera unchanged; an authored stage copy change must preserve
procedural and metric output. The source project must round-trip through
serialization. A mandatory shared BrandProfile blocks colors not allowed for
both stage and procedural original components.

Studio TypeScript integration tests reproduce the same independent project
changes and mandatory BrandProfile refusals.

Independent exact-SHA workflows produce actual native Film H.264/AAC masters
for the original Stage, procedural generator and measured source, plus actual
first-party Chromium capture evidence. The rendered PNG and decoded MP4
checks are not replaced by the editorial Studio SVG preview. Only the exact
integrated PR head can establish that the four code contracts are compatible.

## Explicitly incomplete work

This integration does not certify customer-app captures, legal rights,
creative quality or measurement truth. Remaining requirements include
external authorized capture and visual asset admission to ProductStage,
native 3D device/lighting/camera, general time series and chart grammar,
advanced audio choreography, generation providers, external NLE media,
cache-performance contracts, competitive benchmarking and human creative
user testing.

The requirement-status ledger is the acceptance authority. MW05-E06-03,
E06-04, E07-01 and E07-02 remain partial until their remaining scopes are
independently implemented and accepted.

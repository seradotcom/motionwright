# Source-bound joint native AV master · v0.5

Status: **technical CI experiment**, not an approved campaign or finished
Motionwright v0.5 creative system. This proof uses the existing pinned
Semwright Motion Canvas Driver Host and Motionwright MLT master path, not a
new renderer or private browser automation backend.

## Original project contract

One user-editable StudioService project contains exactly three consecutive
six-second scenes at 1920 × 1080, 30fps:

1. A generic original ProductStage browser silhouette. Its frame, semantic
   screen elements, typography, focus anchor and conspicuous not-a-capture
   disclosure remain individual editable Canvas objects. The fixture's
   author attestation is original-content declaration only, not a rights audit.
2. Eight deterministic procedural rectangles with stable source identities
   and exact 30fps entrance keys. They share one Film z-layer but remain
   eight independent editable native subjects.
3. An authored label and bar whose fixed-point 37.5% value comes from
   an actual separately imported immutable JSON source. The bar has an
   explicit authored 0–100% axis: neither numbers nor bounds are inferred.

The source JSON state and portable .motionwright bundle are retained. A
portable import must rotate the current generation while preserving source
scene objects, measured source assets, field baselines and creative
metadata. All effects remain bound to the original project's native SDK CAS.

## Evidence acceptance

The workflow verifies the exact source Git SHA and exact pinned Semwright
revision, boots a disposable sandboxed Broker and original native providers,
renders 540 source PNG frames, writes a separate distinguishable synthetic
stereo transport WAV and produces an actual H264/AAC MP4.

Independent pixel review examines frames 140, 270 and 480, confirming a
visible original Stage with disclosure and authored text, seven or more
of eight settled procedural objects, and a visible source-bound numeric bar
and label. Distinct source frames must differ in actual image bytes.
A separate ffmpeg invocation decodes the **delivered MP4** at those three
indices and repeats the semantic/frame observations, rather than trusting
the original PNGs or rendering a new preview. The contact sheet contains
native samples, never manufactured third-party screenshots.

A versioned technical receipt binds the exact source state, normalized
scene IDs, SHA-256s, original render and MP4 digest, content sampling,
provider and codec/source identities. Human aesthetic approval is still
required. Synthetic source tones are transport verification only, not
authored sound design or final audio QA.

## Limits and nonclaims

The test **does not** assert end-user delight, conversion gains,
intellectual-property permission for screenshots, external application
capture, verified customer measurements, photorealistic device meshes,
real camera optics or an automatic finished motion design. Exact-HEAD
render/MP4 proof must be green before this acceptance counts.

The parent creative-composition integration and the wider 64-requirement
ledger remain separately governed. This CI proof does not make any of
MW05-E06-03, E06-04, E07-01 or E07-02 complete on its own.

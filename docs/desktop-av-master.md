# Desktop canonical AV master from measured project voice

Motionwright's `Deliver` workspace can invoke the *existing pinned* Semwright MLT audiovisual master operation for one already verified Motion Canvas segment and one already imported, SHA-256-verified measured stereo WAV voice track. The output is the narrow currently certified H.264/AAC, 48 kHz, Rec.709 MP4 profile. This is a true native production action, not a simulated player or generic FFmpeg shell command.

## Owner authority and inputs

The user first saves a delivery profile with an explicit `voice_track_id`, imports/measures a voice WAV through Motionwright's standard content-addressed import boundary, and completes a real authorized Motion Canvas segment render in the same desktop session. Motionwright's read-only native frame registration already creates an opaque session handle *only* after Semwright production/verification and manifest SHA-256 checks.

The `assemble_av_master` Tauri IPC request carries **only** the project ID, exact generation/revision, request/effect-grant ID, saved profile ID, selected voice take ID, and the opaque existing renderer handle. The WebView cannot supply an audio or video source path, arbitrary SHA digest, substitute media/verification JSON, an output destination, process arguments, a Shell command, a driver command or a new provider.

The desktop checks saved profile↔voice binding and resolves the session's exact canonical video source through the private `NativePreviewRegistry`, rejecting invalidated revisions, wrong output profiles or more than one visual segment. The service resolves the source WAV from the immutable project CAS: its asset ID must match the measured VoiceTrack, both SHA-256 values must match, and its declared media type must be WAV. Only **48 kHz stereo** measured tracks pass. The WAV staging boundary accepts bounded RIFF PCM 16/24/32-bit or IEEE float32 audio, rejects malformed/duplicate chunks, validates source size, paths and symlinks, writes to a deterministic create-new owner-private file (mode `0600` on Unix) in the existing owner output root, keyed to the same canonical mastering identity. An identical existing file is reused only after path, byte-size, file-permission and SHA-256 revalidation; mismatched, partial, symlinked or altered staging files are rejected without overwrite. The first write checks exact source byte count and SHA-256. Arbitrary external paths are never read.

Source timing is a separate fail-closed check. The measured voice duration must match the rendered visual segment's rational frame duration within **one 48 kHz sample**. No hidden time-stretching, truncation or padding is allowed. If a voice take and visual cut differ, edit/re-author before attempting a master.

After confirming the project/profile/session-render and exact audio/video timing, the desktop consumes a one-time, project-revision/request-bound **RenderLocal effect grant** **before** any owner-output staging. It then validates and stages the existing measured source WAV through the private service boundary, before asking the existing `ProductionCoordinator::assemble_mlt_av_master` to execute the pinned MLT `frames.encode` and `av.mux` commands through the canonical owner-provisioned Semwright Broker/Driver Host. That coordinator independently validates profile, native film segment, FFV1 mezzanine, H.264/AAC master metadata and SHA-256 output/decoded audio. This does not introduce a parallel scheduler, direct FFmpeg invocation, network server, local generic file API or bypass of native ownership. The native coordinator uses a **deterministic SHA-256-derived request identity** bound to project ID, generation/revision, saved profile, verified visual fingerprint and measured audio SHA-256, independently of the one-time user effect-grant token. Reentering the same logical source cannot bypass the Broker's durable deduplication by minting a fresh native request ID. The canonical request identity also names the staged WAV input, so a safe repeated invocation of the same logical master has an identical Broker argument path. An uncertain command outcome remains uncertain and is not automatically redispatched. A tampered or interrupted stage fails closed for explicit reconciliation; Motionwright never erases it to force a retry.

## Deliberate boundaries

- **Supported now**: one contiguous verified Motion Canvas sequence; an existing measured 48kHz stereo PCM/float WAV; exact voice/video duration; H.264/AAC 48 kHz Rec.709 MP4 owner artifact, with immutable SHA-256 evidence.
- **Not claimed**: multi-segment or mixed-renderer compositing (the [multi-segment source preflight](multi-segment-preflight.md) checks source/manifest readiness but cannot dispatch a final mux), subtitles burned into the media, normalized loudness/true-peak measured compliance, automatically verified cue-level lip/sync matching, audio mixing with music tracks, unbounded or timeline-synchronized AV playback, signed distribution packages or human creative approval. The native master reports its exact revision, frame count and digest in Deliver. [Bounded in-app native MP4 review](native-av-review.md) supports source-verified clips no larger than 16 MiB when the local WebView can decode them. A separate [explicit, SHA-256-verified local MP4 export](master-verified-export.md) supports larger masters, requires its own one-time delivery grant and never exposes generic filesystem reads in the WebView.
- **Audio staging lifecycle**: create-new owner-local staged WAV files cannot overwrite prior media. A successful master retains its proven source for native receipt/recovery correlation; interrupted master operations may leave unreferenced staged media. An independently reviewed garbage-collection policy is a later task, never an unsafe automatic deletion of unknown production artifacts.
- **Project revisions**: a later creative edit makes both segment and master receipts explicitly historical and disallows initiating a new master from them.

## Exact-SHA evidence

The service regression verifies a 48kHz stereo measured import, byte/digest-bound input, rejection of mono, unknown voice IDs and stale project versions. The desktop's WAV tests cover deterministic RIFF validation, readback SHA-256, symlink/size corruption, duplicate chunks, exact rational AV alignment (including NTSC 30000/1001), and output staging. Synthetic Chromium bridge tests prove the UI does not invent a master or transmit unverified files; they are not actual native render evidence.

The existing `native-av-master-e2e` GitHub Actions job runs the *real* pinned Semwright Broker/MLT AV operation on ephemeral runners, followed by an independent [decoded-content gate](native-av-decoded-content.md) that checks non-silent and channel-distinct AAC, 60 decodable H.264 frames and actual motion between sample frames. It is an independent native-runtime gate for the coordinator path, not human installation/media acceptance on the target workstation. CI tests remain tied to the exact PR source SHA. The product's 60 independently reviewed acceptance cases are not automatically promoted by green CI.

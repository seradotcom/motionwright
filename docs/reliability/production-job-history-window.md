# Complete production-job history for Studio

Studio's bounded job list must not be built from a bounded suffix of production receipts. The latest 256 receipts can exclude the original acknowledged native render-start after ordinary status polling; the resulting UI incorrectly labels a successful job `OutcomeUnknown` and replaces its original request identity with a later status request.

The existing complete Native SDK snapshot already defines the authority boundary: obtain the original stream watermark, enumerate an unchanged snapshot, reconstruct jobs with their provider/generation/revision/reference tuple, and refuse a concurrently changed stream. The Studio list now uses **that same read-only snapshot** before truncating its visible result to the existing 1–64-job window. No Native SDK mutation, effect grant, renderer call, second reducer or automatic UNKNOWN retry is introduced.

This is a correctness-over-partial-results choice: when the receipt stream changes during the two read-only phases, Studio returns the existing `ReceiptStreamChanged` error instead of certifying a mixed snapshot. A record history exceeding the existing 20,000-receipt safety limit also reports an explicit error; no silent suffix is promoted as complete. The UI may need a separate paginated/retained historical-job index for very large projects, but that is not authorized by these results and has not been implemented here. The full-snapshot scan has a bounded but larger cost than the old 256-row read; production latency at that scale is NOT_MEASURED.

The integration regression `production_jobs_recent_window.rs` writes an acknowledged original Motion Canvas start, 130 read-only status calls and the original terminal result through `StudioService` into a real SQLite database. Each call uses its original request identity and durable dispatch/completion receipts. With 264 receipts, the old Studio route returns an orphan `OutcomeUnknown` with incorrect `root_request_id`, while the Native SDK complete snapshot returns the original `Succeeded`, 132 validated observations and its correct root request ID. The exact original RED test source is retained at `f241f503f3e832a8035a69bc89063d4fa6180c9e` and its [GitHub Actions failure](https://github.com/seradotcom/motionwright/actions/runs/39065397394).

After correction, the same test checks equality before and after an independent SQLite close/reopen; companion controls verify the existing visible limit, no new receipts from reading, and deterministic rejection of a stale watermark after a new observation. Unit tests do not prove an actual provider job or full installed consumer behavior. The original receipt stream is never rewritten.

Technical coverage is limited to the snapshot authority subcriteria of CR-JOBS-01/03/04/06 and portions of ACC-035/036. A5 retains the formal acceptance decision. This alone does not diagnose the historical provider-generation loss in issue #49 or establish a human review.

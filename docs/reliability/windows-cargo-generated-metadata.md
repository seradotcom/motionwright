# Windows Cargo generated metadata custody

The isolated Windows dependency capture can admit Tauri command-permission files
only through the explicit flag pair:

    --tauri-generated-schemas --tauri-generated-command-permissions

The original schema-only flag continues to emit profile version 1. Without the
new flag, generated command permissions remain unexpected source-tree members.
This is a development source-capture contract, not Graph Save evidence or
distribution acceptance.

## Scope and source authority

Profile version 2 adds only the exact files derived from the tracked
apps/desktop/src-tauri/build.rs. The source descriptor retains its path, Git
blob, observed byte count and SHA-256. Existing Git verification permits only
raw blob bytes or the already authenticated LF-to-CRLF checkout transformation.

The pure helper admits the complete current literal main function, not a search
for any commands call. Additional logic, macros, aliases, dynamic commands or
unrecognized syntax require a deliberate contract change. Command names and
output sizes are bounded; aliases, Windows reserved names and collisions are
rejected.

The authenticated Cargo.lock must contain exactly the reviewed tauri-build 2.7.1
and tauri-utils 2.10.1 registry archive identities. Their SHA-256 pins are in
scripts/tauri_generated_permissions.py. The output template follows
tauri-utils src/acl/build.rs with an empty license header and no schema
reference, as selected by tauri-build src/acl.rs.

## Observation and independent verification

Before metadata and again before the build, the command-permission namespace
must be absent and the admitted source identity must remain unchanged. After
the actual Cargo build, the caller observes exactly one ordinary file per
derived command under:

    apps/desktop/src-tauri/permissions/autogenerated/

Every file must match the expected original UTF-8/LF bytes. Extra files, empty
subdirectories, missing files, links, reparse points, aliases, tracked overlap
and merely self-consistent replacement hashes are rejected.

The license collector independently reads the tracked build script and lock,
derives the roster again, and checks the physical files and descriptors before
and after notice collection. Accepted entries have the distinct kind
TAURI_GENERATED_COMMAND_PERMISSION. They are excluded generated metadata,
never authenticated Git source or license material. Unrelated untracked or
ignored source remains rejected.

Pre/post observation does not prove which process wrote an individual file.
The custody record therefore keeps writer_pid_attribution=NOT_OBSERVED and
does not claim an adversarially atomic filesystem snapshot.

## Retained originals

The existing Windows artifact retains:

- state/tauri-generated-schemas.json, containing the explicit profile version.
- state/generated-metadata/tauri-command-source/build.rs.
- state/generated-metadata/tauri-command-permissions/*.toml.
- The existing four schema originals, Cargo Git markers, source snapshots and
  original metadata/build requests, completions and streams.

Originals are retained before license collection, including when missing
license material prevents capture completion. Collection revalidates the
source and generated metadata before writing capture-complete.json. Retention
uses new files and does not regenerate or overwrite evidence.

The older failed run 42937089323 at source
1b4ef8868a06f4ba9539ec29f6aff288ad8cab67 did not retain these 63 permission
files. Its cargo_notice_coverage_incomplete result remains unchanged.

## Validation scope

Focused tests cover the pure derivation, caller custody and independent
collector, including source/lock changes, forged descriptors, exact namespace
membership and mutations during collection. These are disposable Git and
filesystem contracts; they do not execute Cargo, Native Host or an installer.

The existing package-candidate workflow runs these controls and opts into the
new profile for its isolated Windows capture. A new physical build must still
succeed with complete authenticated notice material. Redistribution permission,
native SQLite/GLib closure, full package inventory and formal G2/G3 acceptance
remain separate requirements.
